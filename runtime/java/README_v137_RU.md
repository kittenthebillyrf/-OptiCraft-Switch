# v137 — аудит точки входа оригинального Minecraft Java 1.2.5

## Цель этапа

Переключаем фокус с дальнейшего расширения временного нативного рендерера на запуск оригинального Java-клиента. Этот этап фиксирует проверенную точку входа и требования к загрузчику; сам клиент на Switch пока не запускается.

## Проверено на пользовательском minecraft.jar

- В JAR найдено 1 152 class-файла.
- Все проверенные class-файлы имеют major version 49 (Java 5 / class-file format 49.0).
- Главный класс клиента: `net.minecraft.client.Minecraft`.
- В нём присутствует `public static void main(java.lang.String[])`.
- Класс `Minecraft` реализует `java.lang.Runnable`.
- В классе есть ссылка на `java.awt.Canvas`; следовательно, одной загрузки class-файлов недостаточно — нужны совместимые графические/AWT-адаптеры.
- Внутренние классы `org.lwjgl.opengl.Display` и `org.lwjgl.Sys` в этом JAR не найдены. LWJGL необходимо рассматривать как отдельную библиотеку/ABI-слой, а не ожидать, что эти классы уже находятся внутри minecraft.jar.
- JAR не содержит `META-INF/MANIFEST.MF` с Main-Class, поэтому launcher должен явно указывать `net.minecraft.client.Minecraft`.

## Контракт будущего launcher

1. Открыть пользовательский JAR по пути `sdmc:/switch/opticraft/minecraft.jar`.
2. Создать classpath с Minecraft JAR и отдельными совместимыми библиотеками.
3. Загрузить `net.minecraft.client.Minecraft` через parent-first class loader.
4. Разрешить метод `main([Ljava/lang/String;)V`.
5. Передать аргументы запуска и обработать исключение верхнего уровня с диагностикой имени класса/метода.
6. Подключить LWJGL 2.x API и платформенные реализации Switch до запуска игрового цикла.
7. Не подменять Minecraft собственной игрой: успешный этап — вызов оригинального метода из пользовательского JAR.

## Блокирующие задачи перед запуском

- Интегрировать частичный JVM runtime в сборку NRO (сейчас его наличие в отдельных инженерных архивах не означает, что он включён в текущий NRO).
- Довести загрузку классов и разрешение зависимостей для всего графа, а не только разбор class-файлов.
- Реализовать недостающие Java SE классы, исключения, строки, коллекции, потоки и синхронизацию, необходимые игровому клиенту.
- Подключить LWJGL 2.x и заменить AWT/Canvas на backend libnx.
- Проверить вызов Minecraft.main на Switch; host-тесты сами по себе не доказывают запуск на консоли.

## Статус

Это аудит и спецификация следующего этапа, а не заявление о готовой JVM. Оригинальный JAR не копируется в репозиторий и не включается в NRO. Пользователь должен предоставить собственный файл на SD-карте.
